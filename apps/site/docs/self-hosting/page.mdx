# Self-hosting

Self-hosting is free. You pay AWS for one Graviton instance with enclaves (about $50 a month for `c6g.large`) and a KMS key ($1 a month). The dashboard and the demo run on Vercel with a Neon Postgres database; both have free tiers.

## What gets created

`infra/aws/stack.yaml` is one CloudFormation stack:

- an S3 bucket for releases and logs
- a KMS key whose policy only allows `kms:Decrypt` from the enclave image you built
- a `c6g.large` instance with Nitro enclaves on, an Elastic IP, and ports 80 and 443 open
- a DynamoDB table (`KeysTable`) for sealed key records, on demand billing, with deletion protection and point-in-time recovery
- an IAM role limited to the bucket, the key, the table and the `/fiducy/*` parameters

The host runs only the gateway enclave and Caddy for TLS. The gateway reads and writes sealed records in `KeysTable` directly and talks to the dashboard over HTTPS with a token that lives in Parameter Store (`/fiducy/gateway-token`).

The dashboard (`apps/control-plane`), the demo (`apps/demo`) and the landing page with these docs (`apps/site`) are Vercel projects, not part of the stack.

## Dashboard and demo on Vercel

Create a Neon Postgres database, then two Vercel projects from this repository. Each app ships a `vercel.json` with its install and build commands.

| Project | Root directory | Environment |
| --- | --- | --- |
| Dashboard | `apps/control-plane` | `DATABASE_URL`, `FARM_AUTH_SECRET` (32 random bytes), `FARM_AUTH_URL` (the project URL), `FIDUCY_GATEWAY_URL` (`https://gw.<your-ip>.sslip.io`), `FIDUCY_GATEWAY_TOKEN` (written by the deploy, see below) |
| Demo | `apps/demo` | `DATABASE_URL` (the same database works), `FIDUCY_GATEWAY_URL`, `FIDUCY_APP_ID` and `FIDUCY_APP_SECRET` of an app you created in the dashboard with the demo URL as an allowed origin |

The dashboard build runs `farm auth migrate` against `DATABASE_URL` before `farm build`, so the auth tables exist on the first deploy.

## Deploy with GitHub Actions

1. Create an IAM user with admin rights for the first deploy.
2. Add repository secrets: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and optionally `AWS_REGION` (default `us-east-1`).
3. Add the repository variable `FIDUCY_CONTROL_PLANE_URL` (the dashboard's Vercel URL) and optionally `FIDUCY_DEMO_URL`.
4. To let the deploy hand the gateway token to the dashboard, add the secret `VERCEL_TOKEN`, the variables `VERCEL_CONTROL_PLANE_PROJECT_ID` and `VERCEL_TEAM_ID` (team accounts only), and the secret `VERCEL_CONTROL_PLANE_DEPLOY_HOOK_URL` (a deploy hook on the dashboard project). Without them the deploy prints where to copy the token from.
5. Run the **AWS deploy** workflow.

The workflow creates the gateway token in Parameter Store on the first run, sets it as `FIDUCY_GATEWAY_TOKEN` on the dashboard project and redeploys it, builds the enclave on the host, reads its `PCR0`, locks the KMS key to it, starts the enclave, and checks the endpoints. The run summary lists your URLs:

```
Gateway (in the enclave): https://gw.<your-ip>.sslip.io
Dashboard (Vercel):       https://<your-dashboard>.vercel.app
```

Tick **rotate_token** on a manual run to replace the gateway token. The new token reaches the dashboard and the enclave in the same run, and the old one stops working.

## Deploy from your machine

```bash
export AWS_REGION=us-east-1
export FIDUCY_CONTROL_PLANE_URL=https://<your-dashboard>.vercel.app
bash infra/aws/deploy.sh
```

Needs the AWS CLI, `jq`, `openssl` and admin credentials. Add `--rotate-token` to replace the gateway token.

## Tear down

Run the **AWS teardown** workflow, or `bash infra/aws/teardown.sh`. The KMS key enters a 7 day deletion window; every key it wrapped becomes unrecoverable after that.

## Run locally

No AWS needed. A local master key stands in for KMS:

```bash
bun install
bun run prototype --mock
```

This starts:

| Port | What | Use it for |
| --- | --- | --- |
| `3000` | Dashboard | Sign up at `/sign-up`, create apps, copy the app ID and secret |
| `3001` | Demo chat | Starts once you add `demoAppID` and `demoAppSecret` for an app with origin `http://localhost:3001` to `.prototype/secrets.json` |
| `8787` | Gateway | `FIDUCY_GATEWAY_URL=http://localhost:8787` in the app you are testing |

Run the app you are testing on another port (for example 5173) and add that origin, such as `http://localhost:5173`, to its allowed origins in the dashboard. `--mock` uses a fake OpenAI that logs the last four characters of the key it received, so you can see decryption happen.

## Gateway environment

| Variable | Purpose |
| --- | --- |
| `FIDUCY_KMS_KEY_ID` | KMS key ARN. When unset, `FIDUCY_MASTER_KEY` is used instead (local only) |
| `FIDUCY_MASTER_KEY` | 32 random bytes, base64url. Local development only |
| `AWS_KMS_ENDPOINT` | KMS proxy inside the enclave. Default `http://127.0.0.1:9999` |
| `FIDUCY_CONTROL_PLANE_URL` | Dashboard URL for app configs, usage and key events |
| `FIDUCY_KEYS_TABLE` | DynamoDB table for sealed key records. When unset, records stay in memory (local only) |
| `AWS_REGION` | Region for KMS and DynamoDB. Default `us-east-1` |
| `FIDUCY_GATEWAY_TOKEN_CIPHERTEXT` | Control plane token, KMS-encrypted |
| `FIDUCY_ENCLAVE_API_URL` | Enclaver API, for `/attestation` |
| `FIDUCY_APPS_JSON` | Static app list when there is no control plane |
| `PORT` | Default `8787` |
