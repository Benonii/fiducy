# Storage

There are two things to store:

- the **handle**, always in your app, through the `storage` adapter you pass to `createFiducy`
- the **sealed record**, either with Fiducy (default) or in your app

## Where sealed records live

Set this per app in the dashboard under "Where sealed keys live".

| Setting | Records live | Notes |
| --- | --- | --- |
| `fiducy` (default) | Fiducy's storage | Smallest setup. Revoke deletes the record on the gateway |
| `app` | Your storage, next to the handle | You own all the data. The SDK sends the record to the gateway in the `x-key-record` header on each call |

In `app` mode the gateway keeps nothing per key. A record is ciphertext plus a KMS-wrapped share, so your database still cannot open a key on its own. Revoking a key means deleting the row; the SDK does this for you.

## Adapters

### keyValueStorage(driver)

Takes any [unstorage](https://unstorage.unjs.io)-style driver: an object with `getItem`, `setItem`, `removeItem` and `getKeys`.

```ts
import { createFiducy, keyValueStorage } from '@fiducy/sdk/server';
import { createStorage } from 'unstorage';
import redisDriver from 'unstorage/drivers/redis';

const storage = keyValueStorage(createStorage({ driver: redisDriver({ url: process.env.REDIS_URL }) }));
```

unstorage has drivers for Redis, Postgres (via `db0`), Cloudflare KV, Vercel KV, the file system and more. On Farm.js, use a storage mount; see [Farm.js](/docs/farm).

Keys are stored as `fiducy:<userID>:<keyID>`.

### memoryStorage()

In-memory, for tests and local experiments. Everything is lost on restart.

### Your own database

Implement four methods:

```ts
import type { FiducyStorage } from '@fiducy/sdk/server';

export const storage: FiducyStorage = {
  saveKey: (key) => db.insert(userKeys).values(key),
  findKey: (userID, provider) => db.query.userKeys.findFirst({ where: { userID, provider } }),
  listKeys: (userID) => db.query.userKeys.findMany({ where: { userID } }),
  deleteKey: async (userID, keyID) => (await db.delete(userKeys).where({ userID, keyID })).count > 0
};
```

A stored key is `{ userID, provider, keyID, handle, record?, createdAt }`. One table is enough:

```sql
create table fiducy_user_key (
  key_id     text primary key,
  user_id    text not null references "user"(id) on delete cascade,
  provider   text not null,
  handle     text not null,
  record     text,            -- JSON, only when records live in your app
  created_at text not null,
  unique (user_id, provider)
);
```

Store `record` as JSON text and parse it back in `findKey` and `listKeys`. The foreign key removes a user's handles when the user is deleted. Treat the handle like a password hash: it is not secret enough to publish, but it is useless without the gateway.
