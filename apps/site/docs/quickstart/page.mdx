# Quickstart

This guide adds Fiducy to a Farm.js app. Other frameworks use the same server instance; see [Server SDK](/docs/server) for a plain route handler. Using assistant-ui? Follow this guide, then [assistant-ui](/docs/assistant-ui).

Starting from nothing? Create a Farm.js app first:

```bash
npm create @farm.js/app@latest my-app -- --template basic --typescript
```

Install the SDK, the Farm.js integration and the AI SDK for the chat route (`npm install` works the same):

```bash
bun add @fiducy/sdk @fiducy/farm ai @ai-sdk/openai
```

## 0. Have a gateway to talk to

Your app needs a running Fiducy gateway and dashboard. Two options:

| Option | Dashboard | Gateway URL |
| --- | --- | --- |
| Local, for trying it out | `http://localhost:3000` | `http://localhost:8787` |
| Your own deployment | Wherever you host it | Its public URL, for example `https://gateway.yourapp.com` |

For the local option, clone the [Fiducy repo](https://github.com/Benonii/fiducy) and run `bun install && bun run prototype --mock`; see [Self-hosting](/docs/self-hosting#run-locally). It takes ports 3000, 3001 and 8787, so run your own app on another port, for example `farm dev --port 5173`.

## 1. Register your app

Sign up in the Fiducy dashboard and create an app. You get:

- an **app ID**, public, used by the widget
- an **app secret** (`fsk_...`), server only, used for every gateway call

Add your site's origin to the app's allowed origins, so the widget can be embedded there. Use the exact scheme, host and port, for example `http://localhost:5173` while developing and `https://myapp.com` in production.

Put the values in `.env` (keep it out of git):

```bash
FIDUCY_GATEWAY_URL=http://localhost:8787
FIDUCY_APP_ID=app_...
FIDUCY_APP_SECRET=fsk_...
```

## 2. Create the server instance

The examples import from `@/`, which points at `src/` through `paths` in your `tsconfig.json`. They use Farm Auth (`auth: { enabled: true }` in `farm.config.ts`, then `bun add @farm.js/auth`); any auth with a server session works.

```ts title="src/lib/fiducy.ts"
import { auth } from '@farm.js/auth/server';
import { getStorage } from '@farm.js/core/storage';
import { createFiducy, keyValueStorage } from '@fiducy/sdk/server';

const { FIDUCY_GATEWAY_URL, FIDUCY_APP_SECRET } = process.env;
if (!FIDUCY_GATEWAY_URL || !FIDUCY_APP_SECRET) throw new Error('Set the Fiducy env vars');

export async function getUserID(request: Request) {
  const user = await auth.user({ request });
  return user?.id ?? null;
}

export const fiducyServer = createFiducy({
  gatewayURL: FIDUCY_GATEWAY_URL,
  appSecret: FIDUCY_APP_SECRET,
  storage: keyValueStorage({
    getItem: (key) => getStorage('fiducy').getItem(key),
    setItem: (key, value) => getStorage('fiducy').setItem(key, value),
    removeItem: (key) => getStorage('fiducy').removeItem(key),
    getKeys: (base) => getStorage('fiducy').getKeys(base)
  }),
  getUserID
});
```

`getUserID` is how Fiducy knows who is asking. Return your own user ID from your auth's server session, or `null` when nobody is signed in. Never take the ID from the request body or a header the browser sets.

Pass `request` to `auth.user`. The routes from step 3 run outside Farm's page request, so `auth.user()` without it throws "No current request is available". With Better Auth, use `auth.api.getSession({ headers: request.headers })` instead.

Farm Auth signs cookies for `http://localhost:3000` in development, which the local prototype already uses. When your app runs on another port, add `FARM_AUTH_URL=http://localhost:5173` to `.env`, or sign-in fails with "Invalid origin".

`storage` is where your app keeps each user's key handle (a reference to the sealed key, not the key). The functions call `getStorage('fiducy')` on every use rather than once at import: this file is also imported by `farm.config.ts`, which loads before Farm sets up its storage mounts, so a storage object captured at import time would not be the `fiducy` mount from step 3.

## 3. Add the integration

```ts title="farm.config.ts"
import { defineConfig } from '@farm.js/core';
import { localStorage } from '@farm.js/core/storage';
import { fiducy } from '@fiducy/farm';

import { fiducyServer } from './src/lib/fiducy';

export default defineConfig({
  storage: {
    mounts: { fiducy: localStorage({ base: '.data/fiducy' }) }
  },
  integrations: {
    byok: fiducy({ instance: fiducyServer })
  }
});
```

The `storage` block defines the `fiducy` mount the server instance reads. Farm's `localStorage` driver writes files on your server under `.data/fiducy` (it is not the browser's localStorage). That is fine while developing; in production, point the mount at a database, for example `postgresStorage({ url: process.env.DATABASE_URL })` from `@farm.js/core/storage`. See [Storage](/docs/storage).

The integration mounts `GET /api/fiducy/keys`, `POST /api/fiducy/keys` and `DELETE /api/fiducy/keys/:keyID`.

## 4. Drop in the widget and use the key

Add a settings page where users connect a key. The app ID is public, so it can go straight into client code:

```tsx title="src/app/settings/page.tsx"
'use client';

import { ConnectKeyWidget } from '@fiducy/sdk/react';
import { useState } from 'react';

export default function SettingsPage() {
  const [connected, setConnected] = useState(false);

  if (connected) return <p>Your OpenAI key is connected.</p>;
  return (
    <ConnectKeyWidget
      gatewayURL="http://localhost:8787" // your FIDUCY_GATEWAY_URL
      appID="app_..." // your FIDUCY_APP_ID
      provider="openai"
      onConnected={() => setConnected(true)}
    />
  );
}
```

To list and remove saved keys, use `useFiducyKeys` from `@fiducy/sdk/react-query` if your app uses TanStack Query, or call `GET` and `DELETE` on `/api/fiducy/keys` yourself. See [React](/docs/react).

Then call the model from any server route:

```ts title="src/app/api/chat/route.ts"
import { createOpenAI } from '@ai-sdk/openai';
import { streamText } from 'ai';

import { fiducyServer, getUserID } from '@/lib/fiducy';

export async function POST(request: Request) {
  const userID = await getUserID(request);
  const settings = userID ? await fiducyServer.providerSettings('openai', { userID }) : null;
  if (!settings) return new Response('Connect your API key first', { status: 400 });

  const { messages } = await request.json();
  const result = streamText({ model: createOpenAI(settings).chat('gpt-4o-mini'), messages });
  return result.toUIMessageStreamResponse();
}
```

## 5. Try it

1. Sign in to your app, open `/settings`, paste a key and save. With `--mock`, any string works, for example `sk-test-1234`.
2. The page switches to "Your OpenAI key is connected."
3. Send a chat request. With `--mock`, the prototype's terminal logs `[fake OpenAI] ... received the decrypted key ...1234`.

If the chat route answers "Connect your API key first" right after you connected one, check the `storage` functions in step 2.

That is the whole integration. The plaintext key only ever exists inside the gateway.
