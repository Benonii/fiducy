# Security

## What runs where

- The gateway runs inside an **AWS Nitro enclave**: no disk, no shell, no network except a fixed egress allowlist (KMS, DynamoDB for sealed records, the instance metadata service for AWS credentials, the provider APIs, the control plane).
- **TLS ends inside the enclave.** Caddy runs in the enclave image next to the gateway, so the parent host only forwards encrypted bytes and never sees a key in transit. The certificate's private key and Caddy's state are sealed with the KMS key, so the host never holds them either.
- The KMS key policy denies `kms:Decrypt` to everyone, account admins included, unless the request carries an attestation document whose image hash (`PCR0`) matches the published build.

## Verify the enclave

```bash
curl "https://gateway.yourapp.com/attestation?nonce=$(openssl rand -hex 16)"
```

The response holds a CBOR attestation document signed by AWS. Check that:

1. the certificate chain ends at the AWS Nitro root certificate,
2. your nonce is in the document,
3. `PCR0` equals the hash produced by building the published enclave image yourself.

Rebuilding the image from the tagged source gives the same `PCR0`. A different hash means different code.

## What it protects against

| Threat | Result |
| --- | --- |
| Your database leaks | Attacker gets handles. Useless without the enclave and your app secret |
| Fiducy's storage leaks | Attacker gets records. Useless without the handles |
| Your server logs leak | Only handles and the app secret appear; rotate the secret |
| Someone with AWS admin on the gateway account | Cannot decrypt stored keys: KMS refuses without the enclave's attestation (keys in transit are exposed until TLS moves into the enclave) |

## Limits

- **Your app secret plus a handle can use a key** through the gateway. Monthly limits per key cap the damage; rotate the secret if it leaks.
- **No plaintext comes back.** There is no endpoint that returns a stored key to your server. The gateway proxy is the only way to use one; ask for a provider the proxy does not cover.
- **The provider sees the key**, as it always does.
- **Hosting**: a flaw in Nitro or KMS would break the guarantees. Self-hosting moves that trust to your own account.
